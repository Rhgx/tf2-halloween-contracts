# Development

## Requirements

- Node.js 26 or newer, with npm.
- Rust (stable, MSVC toolchain) and the [Tauri v2 prerequisites](https://v2.tauri.app/start/prerequisites/) for Windows, which include WebView2.

## Layout

```
src/
  maps.ts                 the map type and list, shared by the UI and the extract script
  halloween-maps.json     generated by scripts/extract-game.ts, embedded in the Rust build
  web/                    the React UI: App.tsx, ContractsView.tsx, RadarView.tsx, SettingsView.tsx, ...
  lib/                    Valve file formats and the TF2 install lookup, used by the extract script
scripts/                  maintainer tools: the map list extract
  lib/                    helpers only the extract needs (the VTF decoder)
public/                   fonts and map screenshots, copied into dist/ by the build
assets/                   icon.svg (the UI favicon) and icon.ico
src-tauri/                the Tauri app: Rust backend and window settings
  src/                    the backend (see below)
  vendor/steam-vent/      a patched copy of the steam-vent crate, see vendor/PATCHES.md
  icons/                  the app icons
.docs/                    these docs
```

Inside `src-tauri/src/`, `main.rs` sets up the window, the tray and startup. `commands.rs` holds the commands the UI calls, `store.rs` the app's own files, `settings.rs` the saved settings, `steam.rs` the sign-in and contract sync, and `game.rs` the TF2 watcher. `tf2/` has the TF2 folder lookup, the process check, the console log reader and the casual queue file. `radar/` has the overlay, the RCON client and the demo reader, and `radar_commands.rs` connects it to the UI.

`data/` holds your Steam token, synced contracts, manual marks, the queue backup, the settings and the radar settings. A debug build (`npm run tauri dev`) keeps it in the repo's `data` folder, created at runtime and ignored by git. Installed builds use `%APPDATA%\tf2-halloween-utils` instead.

## Commands

| Command                                   | What it does                                                                           |
| ----------------------------------------- | -------------------------------------------------------------------------------------- |
| `npm install`                             | Installs the UI and Tauri CLI dependencies.                                            |
| `npm run tauri dev`                       | Runs the app in a development window. Vite serves the UI on port 5174 with hot reload. |
| `npm run tauri build`                     | Release build: the exe under `src-tauri/target/release`.                               |
| `npm run build`                           | Builds the UI into `dist/`, the step the Tauri build runs first.                       |
| `npm run typecheck`                       | `tsc` over the app and the scripts.                                                    |
| `npm run format` / `npm run format:check` | Prettier over the repo. `format:check` is what CI runs.                                |
| `npm run knip`                            | Finds unused files, exports and dependencies.                                          |
| `npm run extract`                         | Rebuilds `src/halloween-maps.json` and `public/maps/`. See below.                      |

In `src-tauri`, run `cargo test`, `cargo clippy --all-targets` and `cargo fmt --check`.

Environment variables: `TF2_DIR` overrides where TF2 is, if the lookup through Steam's registry key and `libraryfolders.vdf` gets it wrong.

Dev builds optimise dependencies (the `[profile.dev]` sections of `src-tauri/Cargo.toml`), so the overlay draws smoothly under `tauri dev`.

## Building

`npm run tauri build` writes the exe to `src-tauri/target/release/tf2-halloween-utils.exe`. There is no installer; the exe is the release. The result is unsigned, so Windows shows a SmartScreen prompt on first run.

npm holds back package install scripts until they are reviewed. The only two in the tree, from esbuild and protobufjs, are not needed and are denied in `allowScripts` in `package.json`; review any new ones with `npm install-scripts ls`.

## Releasing

Bump the version in `package.json`, `src-tauri/Cargo.toml` and `src-tauri/tauri.conf.json`, then push a tag like `v2.0.0`. The release workflow runs `npm run tauri build` on Windows and attaches `tf2-halloween-utils.exe` to a GitHub release for the tag. Releases are Windows only for now; CI only checks that the Linux side still compiles.

## Updating the map list

`npm run extract` needs a local TF2 install on Windows, since it runs the game's `vpk.exe`. It reads the map list and casual menu placement from `items_game.txt`, display names and modes from `tf_english.txt`, and the ConTracker node ids from `proto_defs.vpd`. Screenshots come from each map's TF2 Wiki infobox; for maps the wiki has no screenshot for yet, it falls back to the casual menu thumbnail from `tf2_textures_dir.vpk`, extracted with the game's own `vpk.exe`. Images are saved as lossless WebP through `sharp`, which keeps every pixel at about two thirds the size of a PNG. JPEGs from the wiki are saved as they are, since a lossless copy of a JPEG only preserves its artifacts at about five times the size.

Run it when Valve adds Halloween maps, then check the diff of `halloween-maps.json` before committing. It finds TF2 with `src/lib/tf2-dir.ts`, so `TF2_DIR` works here too.

## Testing safely

The app writes into the TF2 folder and puts the original casual queue back when it quits, so do not point a test build at your real install while the installed app is running. Make a fake game folder with a `tf/console.log` and a `tf/casual_criteria.vdf`, set `TF2_DIR` to it, and run `npm run tauri dev`. Append lines to the fake `console.log` to simulate queueing, joining a match, and map changes.

The app is single instance, so close the installed app first. Otherwise the dev start only shows the open window.

## Style

- TypeScript: two-space indent, single quotes, 120 columns, enforced by Prettier (`.prettierrc`).
- Rust: formatted with `cargo fmt`.
- Comments explain intent or a non-obvious constraint, not what the code already says.
